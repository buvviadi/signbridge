Architecture & Logic

Deep dive into the SignBridge transcription, NLP, and rendering pipelines.

1. Audio & VAD Pipeline

The Python backend streams a 16kHz mono microphone feed using sounddevice. Audio blocks are buffered in 30ms chunks. A dynamic background noise calibrator runs for 1 second on startup to set an RMS threshold. Once voice activity drops below the threshold for ~0.7 seconds, the utterance buffer is finalized and dispatched to the transcription engine.

2. Faster-Whisper Inference

Inference runs entirely locally on the CPU using the base.en model in int8 quantization. This ensures maximum privacy and sub-second transcription latency without requiring external API calls or GPU compute overhead.

3. Rule-Based Gloss NLP

Because true ASL translation requires complex transformer models, this prototype utilizes a deterministic rule-based NLP pipeline (gloss.py):

  • Tokenization & Normalization: Lowercases text and expands contractions (e.g., "don't" -> "do not").
  • Stopword Removal: Purges English filler words (is, am, are, the, a).
  • Lemmatization: Strips suffixes (-ing, -ed, -s) to map inflected verbs to their base dictionary form.
  • Syntax Reordering: Detects WH-question words (who, what, where) and moves them to the end of the token list to mimic basic ASL gloss structures.

4. WLASL Dataset & MediaPipe

The visual vocabulary relies on the Word-Level American Sign Language (WLASL) dataset. Source MP4s are processed via Google's MediaPipe Holistic to extract exactly:

  • 33 Pose/Body landmarks
  • 21 Left-hand landmarks
  • 21 Right-hand landmarks

Missing frames are filled using linear gap-filling, and coordinates are mathematically normalized and smoothed in the browser to ensure the avatar scales properly to any screen size.

PROJECT INFO

About SignBridge

The scope, limits, and future of the prototype.

Academic Prototype

SignBridge was developed as a college major project to demonstrate the feasibility of a real-time, low-latency speech-to-sign avatar pipeline running locally in a browser without heavy 3D rendering engines.

Current Limitations

  • 51 Word Vocabulary: The system only knows 51 specific signs mapped from WLASL.
  • Fingerspelling Fallback: Unrecognized words are currently rendered as text letters on screen. Animated A-Z fingerspelling handshapes are not yet implemented.
  • English Only: Input is restricted to English via the Whisper base.en model.
  • No Facial Grammar: Non-manual markers (eyebrows, mouth morphology) are crucial to real ASL but are excluded from this 2D canvas render.

Future Scope

The architecture is designed to scale. Future iterations aim to replace the 2D Canvas lines with a fully rigged Three.js 3D avatar, expand the dictionary using Indian Sign Language (ISL) datasets, and integrate multilingual Whisper models to support Hindi and Telugu input.

Attribution

Sign videos used for pose extraction are sourced from the WLASL dataset. This project is for academic and demonstration purposes only.
